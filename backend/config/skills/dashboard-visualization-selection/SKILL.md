# Dashboard Visualization Selection (仪表盘可视化类型选择指南)

本 skill 指导智能体如何根据数据特征和用户需求，选择最合适的可视化类型来生成报表。

---

## 核心原则：数据驱动选择

**图表类型的选择应基于数据特征和展示目的，而非用户偏好。**

### 选择流程

```
1. 分析数据结构
   ├─ 识别字段类型（分类、数值、时间）
   ├─ 识别数据关系（对比、趋势、占比、分布）
   └─ 识别数据量（单值、少量、大量）
  ↓
2. 确定展示目的
   ├─ 趋势分析 → 折线图 / 时间序列(timeseries)
   ├─ 对比分析 → 柱状图
   ├─ 占比分析 → 饼图
   ├─ 阈值监控 → 仪表板
   └─ 明细查看 → 表格
  ↓
3. 生成报表方案
```

---

## 1. 图表类型选择规则

### 1.1 折线图 (Line Chart)

**适用场景**：
- 时间序列数据（随时间变化的指标）
- 趋势分析（查看数据增长/下降趋势）
- 多指标对比（同一时间轴上的多个指标）

**数据特征**：
- 包含时间字段（`time`、`date`、`created_at`、`timestamp`）
- 包含数值字段（`value`、`count`、`rate`、`usage`）
- 数据点数量较多（建议 10+ 个时间点）

**典型用例**：
- CPU 使用率随时间变化
- 网络流量趋势
- 请求量随时间变化
- 温度、湿度等环境指标

**示例 SQL**：
```sql
SELECT 
  created_at AS time,
  AVG(cpu_usage) AS cpu_usage
FROM server_metrics
WHERE created_at >= NOW() - INTERVAL 1 HOUR
GROUP BY created_at
ORDER BY time
```

**配置建议**：
- X 轴：时间字段
- Y 轴：数值字段
- 多系列：使用不同颜色区分不同指标
- 平滑曲线：启用 `smooth: true` 使曲线更流畅

> **timeseries（时间序列）**：系统的 `timeseries` 类型是折线图的增强版（仿 Grafana），X 轴为时间，Y 轴可混合使用 Lines/Bars/Points。当需要在一张图里同时展示多条时间序列并灵活切换显示样式时，使用 `type: "timeseries"`。

---

### 1.2 柱状图 (Bar Chart)

**适用场景**：
- 分类数据对比（不同类别的数值对比）
- 排名展示（按数值大小排序）
- 离散数据展示（非连续数据）

**数据特征**：
- 包含分类字段（`name`、`category`、`type`、`node`）
- 包含数值字段（`value`、`count`、`total`）
- 分类数量适中（建议 5-20 个类别）

**典型用例**：
- 各服务器 CPU 使用率对比
- 各机房带宽使用率排行
- 各业务线请求量对比
- 各状态码数量统计

**示例 SQL**：
```sql
SELECT 
  server_name,
  AVG(cpu_usage) AS cpu_usage
FROM server_metrics
GROUP BY server_name
ORDER BY cpu_usage DESC
LIMIT 10
```

**配置建议**：
- X 轴：分类字段
- Y 轴：数值字段
- 排序：按数值大小排序（升序或降序）
- 横向柱状图：当分类名称较长时使用

---

### 1.3 饼图 (Pie Chart)

**适用场景**：
- 占比分析（各部分占总体的比例）
- 分布展示（数据在不同类别中的分布）
- 少量分类（建议 3-7 个类别）

**数据特征**：
- 包含分类字段（`type`、`status`、`category`）
- 包含数值字段（`count`、`total`）
- 分类数量较少（建议 ≤ 7 个）

**典型用例**：
- 各状态码占比
- 各业务线流量占比
- 各机房服务器数量占比
- 各设备类型分布

**示例 SQL**：
```sql
SELECT 
  status_code,
  COUNT(*) AS count
FROM api_requests
GROUP BY status_code
```

**配置建议**：
- 分类字段：作为扇形名称
- 数值字段：作为扇形大小
- 标签：显示名称和百分比
- 颜色：使用不同颜色区分各扇形

**注意事项**：
- 分类过多时（>7 个），考虑使用"其他"合并小类别
- 饼图不适合展示精确数值，只适合展示大致比例

---

### 1.4 仪表板 (Gauge)

**适用场景**：
- 单值监控（当前值与阈值的对比）
- 进度展示（完成度、使用率）
- 状态指示（正常/警告/危险）

**数据特征**：
- 单个数值（0-100 的百分比或 0-max 的绝对值）
- 明确的阈值（如 80% 为警告，90% 为危险）

**典型用例**：
- CPU 使用率
- 内存使用率
- 磁盘使用率
- 任务完成度

**示例 SQL**：
```sql
SELECT 
  AVG(cpu_usage) AS cpu_usage
FROM server_metrics
WHERE server_name = 'server-01'
```

**配置建议**：
- 数值范围：0-100（百分比）或自定义范围
- 阈值颜色：
  - 绿色：0-50%（正常）
  - 青色：50-80%（注意）
  - 蓝色：80-100%（警告）
- 指针：显示当前值位置
- 标签：显示数值和名称

**注意事项**：
- 仪表板只适合展示单个数值
- 不适合展示多个指标或多个时间点的数据

---

### 1.5 表格 (Table)

**适用场景**：
- 明细数据查看（查看具体数据值）
- 多维度数据（需要查看多个字段）
- 精确数值（需要查看准确数值而非趋势）

**数据特征**：
- 多列数据（需要查看多个字段）
- 行数据较多（需要分页或滚动查看）
- 需要排序、筛选、搜索

**典型用例**：
- 服务器列表（名称、IP、状态、CPU、内存）
- 告警记录（时间、级别、内容、状态）
- 用户列表（用户名、邮箱、角色、创建时间）
- 订单明细（订单号、金额、状态、时间）

**示例 SQL**：
```sql
SELECT 
  server_name,
  ip_address,
  status,
  cpu_usage,
  memory_usage,
  last_seen
FROM servers
ORDER BY last_seen DESC
LIMIT 100
```

**配置建议**：
- 列顺序：将重要字段放在前面
- 列宽：根据内容自动调整
- 排序：支持点击列头排序
- 分页：数据量大时启用分页（每页 10-50 条）
- 条件告警：使用颜色高亮异常值

**高级功能**：
- 合并单元格：相同值的单元格合并
- 条件告警：超过阈值的单元格高亮
- 列筛选：支持按列筛选数据
- Data Links：单元格可点击跳转到详情页

## 2. 数据特征识别规则

### 2.1 字段类型识别

| 字段特征 | 字段类型 | 适合的图表 |
|----------|---------|-----------|
| 字段名含 `time`/`date`/`created_at`/`updated_at`/`timestamp` | 时间字段 | 折线图 X 轴 |
| 字段名含 `name`/`category`/`type`/`node`/`status` | 分类字段 | 柱状图 X 轴 / 饼图分组 |
| 字段名含 `value`/`count`/`total`/`num`/`qty` | 计数指标 | 柱状图 / 折线图 Y 轴 |
| 字段名含 `rate`/`ratio`/`percent`/`usage`/`利用率`/`使用率` | 比率指标 | 仪表板 / 折线图 |
| 字段名含 `avg`/`max`/`min`/`sum` | 聚合指标 | 折线图 / 柱状图 |

### 2.2 数据关系识别

| 数据关系 | 识别特征 | 推荐图表 |
|----------|---------|---------|
| 时间趋势 | 包含时间字段 + 数值字段 | 折线图 |
| 分类对比 | 包含分类字段 + 数值字段 | 柱状图 |
| 占比分布 | 分类字段 + 数值字段（占比场景） | 饼图 |
| 阈值监控 | 单个数值（0-100） | 仪表板 |
| 明细查看 | 多列数据 | 表格 |

### 2.3 数据量识别

| 数据量 | 识别特征 | 推荐图表 |
|--------|---------|---------|
| 单值 | 1 行 1 列 | 仪表板 |
| 少量分类 | 3-7 个类别 | 饼图 |
| 中等分类 | 5-20 个类别 | 柱状图 |
| 大量时间点 | 10+ 个时间点 | 折线图 |
| 多列数据 | 5+ 列 | 表格 |

## 3. 报表组合方案

### 3.1 监控类报表

**场景**：服务器监控、网络监控、应用监控

**推荐组合**：
1. **仪表板**（顶部）：展示关键指标（CPU、内存、磁盘使用率）
2. **折线图**（中部）：展示指标趋势（过去 1 小时的 CPU 使用率）
3. **柱状图**（下部）：展示各服务器对比（各服务器 CPU 使用率排行）
4. **表格**（底部）：展示明细数据（服务器列表及详细信息）

**示例**：
```json
{
  "panels": [
    { "id": "", "title": "CPU 使用率", "type": "gauge", "gridPos": { "x": 0, "y": 0, "w": 8, "h": 8 } },
    { "id": "", "title": "内存使用率", "type": "gauge", "gridPos": { "x": 8, "y": 0, "w": 8, "h": 8 } },
    { "id": "", "title": "磁盘使用率", "type": "gauge", "gridPos": { "x": 16, "y": 0, "w": 8, "h": 8 } },
    { "id": "", "title": "CPU 使用率趋势", "type": "line", "gridPos": { "x": 0, "y": 8, "w": 24, "h": 8 } },
    { "id": "", "title": "各服务器 CPU 使用率排行", "type": "bar", "gridPos": { "x": 0, "y": 16, "w": 24, "h": 8 } },
    { "id": "", "title": "服务器列表", "type": "table", "gridPos": { "x": 0, "y": 24, "w": 24, "h": 10 } }
  ]
}
```

### 3.2 业务分析类报表

**场景**：业务数据分析、用户行为分析、销售数据分析

**推荐组合**：
1. **折线图**（顶部）：展示业务趋势（日活用户、订单量）
2. **柱状图**（中部）：展示分类对比（各业务线订单量）
3. **饼图**（下部）：展示占比分布（各状态订单占比）
4. **表格**（底部）：展示明细数据（订单明细）

### 3.3 运维告警类报表

**场景**：告警管理、故障排查、性能分析

**推荐组合**：
1. **仪表板**（顶部）：展示关键指标（当前告警数、异常率）
2. **折线图**（中部）：展示告警趋势（过去 24 小时告警数）
3. **柱状图**（下部）：展示告警分布（各级别告警数量）
4. **表格**（底部）：展示告警明细（告警列表）

## 4. 最佳实践

### 4.1 布局原则

- **从上到下**：关键指标 → 趋势分析 → 对比分析 → 明细数据
- **从左到右**：重要指标放在左侧
- **合理间距**：面板之间保留 1 个单位间距
- **统一高度**：同一行的面板高度保持一致

### 4.2 颜色使用

- **一致性**：相同指标使用相同颜色
- **语义化**：
  - 绿色：正常、成功
  - 黄色/橙色：警告、注意
  - 红色：错误、危险
  - 蓝色：信息、中性
- **对比度**：确保文字和背景有足够对比度

### 4.3 标签和标题

- **清晰的标题**：每个面板都应有明确的标题
- **单位标注**：数值应标注单位（%、MB、次/秒）
- **图例说明**：多系列图表应显示图例
- **轴标签**：X 轴和 Y 轴应有标签说明

### 4.4 性能优化

- **数据量控制**：
  - 折线图：建议 ≤ 1000 个数据点
  - 柱状图：建议 ≤ 50 个类别
  - 饼图：建议 ≤ 7 个类别
- **查询优化**：
  - 使用时间范围过滤（`WHERE created_at >= NOW() - INTERVAL 1 HOUR`）
  - 使用聚合函数（`AVG`、`SUM`、`COUNT`）减少数据量
  - 使用 `LIMIT` 限制返回行数

## 5. 常见场景示例

### 场景 A：服务器监控

**数据**：
```
server_name | cpu_usage | memory_usage | disk_usage | status
server-01   | 45.2      | 68.5         | 72.3       | running
server-02   | 78.9      | 82.1         | 65.8       | running
server-03   | 92.5      | 91.3         | 88.7       | warning
```

**推荐方案**：
1. **仪表板** × 3：CPU、内存、磁盘使用率
2. **折线图**：过去 1 小时 CPU 使用率趋势
3. **柱状图**：各服务器 CPU 使用率对比
4. **表格**：服务器列表及详细信息

### 场景 B：API 监控

**数据**：
```
status_code | count | avg_response_time
200         | 15234 | 45.2
404         | 234   | 12.5
500         | 56    | 234.8
```

**推荐方案**：
1. **仪表板** × 2：总请求数、错误率
2. **折线图**：请求量趋势（按时间）
3. **柱状图**：各状态码请求数量
4. **饼图**：各状态码占比
5. **表格**：状态码明细

### 场景 C：业务分析

**数据**：
```
business_line | order_count | total_amount | avg_amount
电商          | 1234        | 567890.50    | 460.25
金融          | 567         | 890123.75    | 1570.12
教育          | 890         | 234567.80    | 263.56
```

**推荐方案**：
1. **折线图**：各业务线订单量趋势
2. **柱状图**：各业务线订单量对比
3. **饼图**：各业务线订单量占比
4. **表格**：业务线明细数据

## 6. 注意事项

1. **不要过度可视化**：不是所有数据都需要图表，有时表格更直观
2. **选择合适的粒度**：数据点太多时，考虑聚合（如按小时/天聚合）
3. **考虑用户场景**：
   - 运维人员：关注实时状态和告警
   - 业务人员：关注趋势和对比
   - 管理层：关注关键指标和总结
4. **测试和迭代**：创建后让用户试用，根据反馈调整

## 7. 快速决策表

| 你想展示什么？ | 数据特征 | 推荐图表 |
|---------------|---------|---------|
| 某指标随时间如何变化？ | 时间 + 数值 | 折线图 / timeseries |
| 不同类别的数值对比？ | 分类 + 数值 | 柱状图 |
| 各部分占总体的比例？ | 分类 + 数值（占比） | 饼图 |
| 当前值是否在正常范围？ | 单个数值（0-100） | 仪表板 |
| 查看具体数据值？ | 多列数据 | 表格 |
| 数据在不同维度的分布？ | 多分类 + 数值 | 柱状图 / 饼图 |
| 多个指标的趋势对比？ | 时间 + 多个数值 | 折线图（多系列） |

## 8. 与 dashboard-panel-editing skill 的配合

本 skill 应与 `dashboard-panel-editing` skill 配合使用：

1. **分析数据**：使用 `dashboard-data-query` skill 查询数据
2. **选择图表**：使用本 skill 的规则选择合适的图表类型
3. **创建报表**：使用 `dashboard-panel-editing` skill 的 `update_draft` 指令创建报表

**示例流程**：
```
用户：帮我创建一个服务器监控报表
  ↓
智能体：
1. 查询数据结构（使用 dashboard-data-query skill）
2. 识别数据特征（时间字段、分类字段、数值字段）
3. 选择图表类型（使用本 skill 的规则）
4. 生成报表方案（仪表板 + 折线图 + 柱状图 + 表格）
5. 创建报表（使用 dashboard-panel-editing skill 的 update_draft）
```

---

## 9. 总结

选择合适的可视化类型是创建有效报表的关键。记住以下原则：

- **时间序列 → 折线图**
- **分类对比 → 柱状图**
- **占比分布 → 饼图**
- **阈值监控 → 仪表板**
- **明细查看 → 表格**

通过分析数据特征、明确展示目的、遵循最佳实践，你可以创建出直观有效的报表，帮助用户快速理解数据并做出决策。
